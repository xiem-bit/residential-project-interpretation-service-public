# Product 5 Presales Focus

## Outcome

Produce a runnable, project-specific residential UE presales prototype from frozen upstream business semantics. Reuse `tools/product5_shell/` as the single runtime implementation. Do not let the web carrier invent competitors, customers, value anchors or super-competitiveness judgments.

## Required inputs

Read:

1. `AGENT_RULES.md`
2. `core/08-产物5交互蓝图.md`
3. `tools/product5_shell/README.md`
4. the current project contract, Product 1, Product 2 when enabled, semantic core, established SCs, Product 3 Chapter 3 handoff and Product 5 interaction blueprint

Stop project-specific production when fewer than three SCs are established, the interaction blueprint is blank, or current-project copy cannot be written from approved facts and judgments.

## Production workflow

1. Freeze the project name, value anchor, three to four SCs, family tasks, comparison boundaries, UE scenes, project facts and open high-risk facts.
2. Copy the runtime into the current project output area. Replace all content in `public/project-data.js`; never edit the shared gold source with real-project facts.
3. Keep the default desktop structure: full-screen scene background, two translucent information layers, bottom primary navigation and hover/focus secondary band.
4. Produce city relationship, red-line community garden and homecoming UE scenes by default. Omit any of the three only after a human explicitly approves the exception in the current interaction blueprint.
5. Build each main chapter around one customer judgment. The page must add a distinct relationship, action or visual proof; do not repeat the same conclusion in different skins.
6. Build the AI advisor from meaningful life conditions rather than decorative questions. Each route must contain one direct recommendation, the customer situation, exactly three project reasons, a three-step visit order, two comparison conditions and one next action.
7. Write customer copy from the developer-marketing viewpoint. Keep information density high while removing schema names, evidence gaps, source status, validators, internal IDs, production tasks and requests for the client to decide internal work.
8. Bind each route to an independent image, desktop result and phone page. The phone page must consume the same route object rather than a second copy of the text.
9. Keep number, button, chapter, generation and result motion. Respect `prefers-reduced-motion`; preload persistent scene images and avoid blank transitions.
10. Run `npm ci --ignore-scripts`, `npm test` and the repository static-bundle checks. Then inspect the production build in a real browser at 1600×900 and 390×844, exercising every main chapter, one complete advisor route, the result scroll and both mobile entry types.
11. Scan source, build and screenshots for source-project names, domains, accounts, absolute paths, credentials, private client materials and old route text. Any hit blocks handoff.
12. Record local machine checks, browser visual review, human acceptance, publication and business effect as separate states.

## Visual asset boundary

Allowed visuals are public-safe company cases with registered semantics, system-made maps or diagrams, semantically reviewed generated visuals, and client-render derivatives only after the separate authorization required by the current project.

Raw client PDF, WeChat, proposal and effect-image screenshots never enter the formal prototype. Cropping, recoloring, masking, recaptioning or light redrawing does not change that status. Every formal image needs an asset-register entry with source type, asset identity, business semantics, proof purpose and destination.

## QR and publication boundary

The source includes QR capability but displays a code only when `VITE_PUBLIC_BASE_URL` is a real, reviewed HTTPS address. Do not place a fake public URL into the prototype. External hosting, account creation, access control, expiry and release remain separate actions requiring current authorization and live verification.

## Completion standard

The first user-review build is complete, project-specific, runnable and visually inspected. It contains no empty slots, placeholder copy, missing images, internal-status panels or fake public links. The Qinglan gold reference proves the production method only; it never supplies facts or conclusions for another project.

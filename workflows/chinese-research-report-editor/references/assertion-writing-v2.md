# 断言写作 v2.0：让中文业务表达像真人说话

版本：2.0 · 2026-09-04

本规范由本机全局 `chinese-research-report-editor` 维护，供各工程调用。它继承结论先行、肯定式表达、内容保真、结论与支撑相邻等原则，吸收用户对课件的真人改稿及后续裁定。例子说明写法，不构成其他工程的事实或固定措辞。

## 1. 判断标准

目标读者不需要先翻译一遍 AI 概念，就能看懂这句话在谈谁、判断什么、依据是什么，以及对当前业务有什么用。

“像人话”重在含义清楚、说话者明确、语气自然。字数、否定词数量和术语命中不能单独判断文案质量。断言应明确已有判断，不提高事实的确定性，不把推测改成承诺。

## 2. 优化原则

### P1 先交代业务用途

说明读者为何需要这份研究、方案或产品，它会改变什么判断、选择或行动。只有当读者确实关心制作和交付差异时，才介绍产物形态、页面组织或生产方式。

业务用途已有依据时直接写清；依据不足时保留真实限制，不用“赋能、闭环、形成答案”等词遮住缺口，也不补造效果。

客户版正文交付已有的业务判断，不把“建议补研究、后续再核验”等内部待办当作主结论。确实需要客户参与的业务动作可以明确写出，但要说明其目的；内部工作安排按任务需要另列。

### P2 写完整，比写短更重要

补全主语、动作、对象及省略的关系。一个长句能够顺着读懂，可以保留；短句让人猜“谁的改变、什么答案、怎样承接”，就应展开。删除赘述，不删除必要语义。

“这次改变”可以改成“这次最想获得的改变”。字数增加，但指代更清楚。不要把审稿变成统一缩句，或一律拆成碎片式短句。

### P3 用实际动作解释抽象关系

当“闭合、投影、母体、底盘、货架、承接、收束、语义”等词让读者猜测时，说明实际发生了什么：谁拿什么比较、谁提供什么、怎样作出选择、选择后能得到什么。

这些词不设全局禁用表。读者熟悉、已经定义或确实承担专业区别的概念可以保留；首次使用可配一个具体解释。不用新的抽象词替换旧的抽象词，也不通过堆日常细节降低原有的战略层次。

### P4 把判断写在前面，保持真实的确定性

有依据的观点直接说清，优先陈述实际成立的因果、条件、分工或比较。不要用装饰性的“不是……而是……”制造洞见，也不要为了套“凭 A、靠 B”而编出机制。

真实对比、必要否定、风险和能力限制可以保留。用户已经认可的说话方式不因包含转折词就被机械改写。项目对特定正式载体有明确更严格要求时，按该任务执行，不推广到所有文体。

### P5 标题概括判断，正文保留理解所需的信息

论证页的标题直接说业务判断或结果，副标题解释关系。介绍性标题可以直接点明对象，不为凑“洞见”添加未经正文支持的结论。全文标题与副标题连读，应能抓住主要意思。

报告、课件可以保持高信息密度。正文负责事实、案例、比较和推导，读者自己阅读也能懂。不要把所有机制挤进标题，不把正文压成口号；文案增长时按实际载体调整版位和换行，不以删除论据、裁剪原声或缩到难读的字号解决。

### P6 删除重复自证，保留真正需要学习的判断

同一原则放在最适合的位置讲透，其他位置只保留必要承接。删去反复解释“我们不是做什么”、历史验收评价、制作提醒和无关的下一步生产安排。

按受众区分：

- 客户方案：重点写客户问题、比较判断、具体价值与方案建议。
- 内部培训：可以讲方法、系统和协作，但应带真实例子，讲清为什么这样判断，以及结果怎样改变。
- 操作说明或审计材料：保留完成任务所需的步骤、来源和记录，不为“去 AI 腔”删掉功能性内容。

不要在已经成立的收口句后习惯性续写内部方法论。用户让删除的流程提示，也不要换个说法补回。

### P7 保留专业性与真人语气

尊重作者已经形成的判断强度、业务口吻及读者熟悉的专业用语。正式、口语、直接、有态度都可以自然，不强制改成中性的说明书，也不滥加俚语、感叹、反问或“我们”。

例如，特定销售培训中的“站得住脚，不得虚”可以保留；不能据此要求所有报告都用这种语气。“购房任务”“超级竞争力”等在对应工程有明确含义时保留。“唯一或最”不因措辞本身被套上统一免责声明，但写作偏好也不能代替真实依据或扩大具体承诺。

### P8 让例子支撑判断，原声保持原声

用已有事实说明问题、判断和变化之间的联系；例子要帮助理解业务，而非仅证明“做过研究”。培训中的真实用户指令可以是主体内容。

不补造人物、项目、数字、客户提问或原话。客户原声、专名、已锁定事实保留，分析与原声分开。结论附近放足以理解的支撑；完整来源和核验过程按任务需要留在后台或附录。项目允许的官方价值可正面说明客户意义，价格、权益、学区、交付等承诺仍按当前事实口径。

## 3. 从真人改稿提炼原则的工作方式

1. 找到用户实际修改后的版本，与可确认的修改前版本对照。区分文字改写、删除、移动和纯版式变化；没有原版时说明只能从现稿归纳，不能编造修改意图。
2. 从显著的真实改动解释作者在改善什么，用“原来怎样写、用户怎样改、解决什么问题”支撑归纳。不要把猜测当作用户已确认的永久偏好。
3. 反查全文的同类表达，兼顾标题、正文、表头、图注和结尾。保留已自然且有业务含义的句子，不为统一风格重新加工全篇。
4. 用户要求先裁定时，逐项列出实际位置、原句、建议句和理由。将错字、页码、名词或行动不一致与风格建议分开，等待正文修改授权。
5. 获授权后只改已批准范围及必要的衔接。保留手工改动、锁定内容和原始文件，按工程约定形成新版本；再检查主语、逻辑、术语、数字、阶段要求和跨页引用是否同步。

## 4. 有代表性的改写

以下为经本轮裁定采用的写法或匿名化示例。按真实语境使用，不当作跨项目事实。

| 原表达 | 更自然的表达 | 改善点 |
| --- | --- | --- |
| 明确当前要推动的判断，调用对等产物。 | 这次拜访要让甲方认同什么，就准备相应的产物。 | 从系统调用改为销售的实际目的与动作。 |
| 共同基座向下投影为四项具体产物。 | 四个产物共用这些事实和判断，分别解决不同问题。 | 把“投影”的含义说出来，保留共用关系。 |
| 本案与竞品的事实对称。 | 本案和竞品各自能提供什么，是否按同一标准比较。 | 补出比较对象和动作。 |
| 项目产品底盘与片区价值母体被分开。 | 分清片区规划与项目实际能提供的条件，再判断哪些能成为购房者真正享有的价值。 | 解释差异为什么影响购买判断。 |
| 这次改变。 | 这次最想获得的改变。 | 增加字数以补全指代，不做机械缩句。 |
| 这次改善改变的触发。 | 这次为什么想换房。 | 换成读者会使用的动词句。 |
| 每一条竞争力都必须闭合四步。 | 每一条竞争力，都要把这四件事说清楚。 | 保留判断要求，去掉处理术语。 |
| 案例语义是否与本案一致？ | 案例展示的购买理由，是否也适用于本案？ | 直接指出需要判断的具体关系。 |
| 业务语义一致，体验结构不同。 | 让甲方看到，我们知道怎样用系统持续服务购房者。 | 在介绍业务用途的页面，将重心从制作差异转向客户认可的能力。 |

## 5. 防止越改越像 AI

- 不强制所有标题塞入“对象＋机制＋结果”，不强制每句改成“凭 A、靠 B”。
- 不把“肯定式优先”变成删光否定、转折和限制，不把清晰判断变成无条件承诺。
- 不把“人话”变成省略主语、概念碎片、整齐三段式或情绪化口号。
- 不为了口语化丢失复杂判断、战略层次、完整论据或高密度正文。
- 不给专业术语建无条件黑名单，不把真实原声润色成作者想说的话。
- 不把审核过程和“我如何生成这段话”的解释放回业务正文。

## 6. 最短有效检查

通读时检查：读者是否知道这句话在谈什么，业务关系是否说完整，事实与判断是否相称，是否保留作者的语气，前后说法是否一致。正式 PPT、PDF、HTML 再查看实际版面，防止改写后出现断句、遮挡和引用错误。

机械扫描只定位疑点，不判定文案合格，不要求零命中，不替代阅读。小范围改字做局部回读即可，只有任务明确要求或风险相称时增加扫描、对照记录与正式验收；这些过程信息默认留在后台。


## 7. 从研究母稿到读者可用正文（2026-09-05真实任务补充）

面向客户的研究报告，默认在正式排版前完成一次读者口吻编辑：研究母稿完成 → 目标受众口吻全文编辑 → 排版导出 → 检查受影响页面。由当前作者切换视角完成，不新增独立Agent、审批、评分或测试系统。用户已经认可主体并限定修订范围时，只做局部定稿，不重复全文编辑。

先连读结论和标题，再逐页读正文、表格、标签和非引文说明。将“需要讲清、应进一步解释、接受检验”等尚未完成的写作任务，改成已有的业务判断；有对象和用途的营销或经营建议继续保留。写清被抽象词省略的人、动作和条件；材料只支持总价超预算，就写总价，不能擅自补成首付不足、月供困难或没有购买能力。

改写的完成标准同时包括读者更容易理解、事实与判断没有变坏。尤其守住：喜欢与购买、超出预算与无购买能力、规划与实景、尚未取得与尚未发布、推演客群与实际客源。条件写在它真正限制的判断上，不能把成交条件倒挂成吸引力成立的前提。

影响读者判断的资格、历史价格、分期交付、效果图性质留在对应内容旁；样本处理、检索过程和名单管理留在底稿。“未将个人教育考虑升级为入学权益”是内部记录；“教育考虑为购房者个人诉求，不代表项目入学权益”是客户可读说明。

### 房地产营销研究：白描写选择，肖像写可争取的需要

写作身份是资深房地产营销策划向开发商提交研究，保留户型、总价段、首开、在售房源、交付批次、架空层、洋房等有明确含义的行业用语。不要用模型缩写替代购房问题，也不要换成空泛广告语。

客户白描围绕材料中真正发生的事情连贯叙述：原来怎样生活，为什么现在买房，看过什么，喜欢什么、顾虑什么，最后怎样决定或为什么还在等。原声原样保留，分析另写；缺失的生活细节、动机和结局不补造。年龄、职业不代替购买过程，官方活动和营销人物不冒充真实家庭。

客群肖像由事件中的共性、分歧与本案事实推导：他们想改善什么、最难让步什么、本案为什么值得考虑。写成营销团队能讨论的家庭需要，不写成“至少命中一项＋支付匹配”的模型筛选规则，也不冒充已掌握的实际客源。不同需要可分别成立、也可同时出现在一家人身上，不把全部最佳条件变成购房资格。

例如，白描可以写“她认可远大的通勤和父母距离，也介意住宅使用感受，仍在比较云锦66”；肖像则写“婚后仍希望上班和探望父母方便的家庭，是可重点争取的需求”。前者描述已有记录，后者是以本案位置为条件的营销推演，两者身份保持清楚。

### 用完整改写示范保留判断

| 修改前 | 修改后 | 保住的区别 |
|---|---|---|
| 本案接待应区分价值认同与支付匹配。 | 客户已经喜欢小区、只是总价超预算时，销售应提供预算内的真实房源，或在价格变化后再跟进。重复介绍公园、会所等卖点，难以解决总价超预算的问题。 | 喜欢仍成立，总价阻止购买；没有推断首付或月供困难。 |
| 本案相应面积、支付及窗口重合时，进入直接比较。 | 本案开盘时，若对方仍有相近面积、相近总价的房源在售，将形成直接竞争。 | 可同时购买才有替代，不要求同期开盘，也不把候选直接写成确定竞品。 |
| 本案要把连续绿轴的使用关系讲清楚。 | 公区配套已是多个竞品的共同卖点，本案的特色在于绿轴串联三公园。 | 交付比较判断；规划特色不自动代表全面领先。 |
| 对三项所得中至少一项有明确偏好、又能容纳具体支付与入住安排的人。 | 本案值得重点争取的，是希望换房后仍方便上班或探望家人、重视小区公园与活动空间，或偏爱六层洋房的改善客户。户型是否合用、总价能否承担、交房时间是否符合入住计划，决定他们是否最终购买。 | 多种需求分别成立，兴趣与最终购买分开。 |
| 公区配套有吸引力的前提，是客户愿意使用，总价和交房时间也能接受。 | 公区配套是否有吸引力，取决于它是否符合家人的日常需要；这种吸引力能否转化为购买，还要看总价和交房时间。 | 语言通顺后仍检查原有分析层次，预算不消除吸引力。 |

上述案例来自红星路TOD定稿编辑，只迁移比较与表达方法，不迁移楼盘事实、人物、客群、卖点或页数。下一次制作中，竞品页讲清为什么有人买，横向页讲清客户怎样取舍，总论页讲清本案争取谁；避免每页重复同一条“户型、总价、交房还要合适”的总结。本次已被用户认可的结构，不因此重排。

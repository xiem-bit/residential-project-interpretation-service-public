# 甲方成果断言式写作与后台隔离

本参考随现有住宅生产总控按需加载，适用于产物1、产物2以及客户可见的PPT、HTML、PDF和网页文案。它管理表达与交付边界，不改变项目事实、竞争判断或客户任务。

## 一、A／B／C三级执行强度

| 层级 | 对象 | 执行要求 |
| --- | --- | --- |
| A｜强制语义审校与扫描 | 价值锚点、超级竞争力、策略标题、PPT可见主标题、核心论点与金句 | 标出否定、转折、话题标签和程序化压缩；提取完整语义；完成肯定式改写、语义覆盖和so-what测试；运行机械扫描。命中必须人工复核，不要求全文零命中 |
| B｜正式交付报告式扫描 | 正文判断句、小节句、卡片观点与支撑 | 普通讨论和中间稿不默认扫描；正式交付前使用`--report-only`整体扫描，只改写削弱结论、制造歧义或暴露内部方法的命中 |
| C｜内容优先、默认豁免 | 客户原声、甲方专名、事实数据、竞品适配边界、风险限制、法律／合同表达、历史记录与小范围事实修订 | 保持原意、事实和诚实性；必要否定可以保留；用户提出更严格要求时再升级 |

机械扫描只负责定位。命中表示需要人工复核，不自动表示文本错误；扫描通过也不证明事实、策略、营销语言或甲方接受已经成立。

## 二、标题和高影响句直接断言业务机制

1. 标题包含业务对象、判断及成立机制或条件，并通过“所以呢”测试。全文标题连读应能还原报告主线。“市场分析、竞争格局、策略建议、核心结论”等话题标签不能独立充当标题。
2. “不是……而是……”“虽然……但是……”“不能只……还要……”等句式先提取真正成立的判断，再改写为分层、条件、过程、裁定或分工关系。
3. 常用正向结构包括：
   - 凭A进入X，靠B赢得Y；
   - A先定基础，B再完成裁定；
   - A与B相连，C才成为D；
   - C只对具备B的对象成立；
   - X由A／B／C共同裁定，每一项都握有否决权；
   - A促成X，B完成Y。
4. 改写必须保留原句的事实、条件、比较关系、客户任务与行动含义。禁止只删除否定词，禁止用更短的句子替代完整语义。
5. 高影响或存在争议的句子形成“主推句＋备选＋一句改造理由”供审校；普通句直接采用最优表达。正式成果只保留最终采用句。

## 三、甲方正文只呈现业务世界

1. 正文直接呈现市场事实、产品关系、客户选择、项目价值、比较边界和行动建议。
2. 搜索过程、证据等级、候选状态、系统字段、内部编号、验证结果、工具失败、生产方法、回执和后台待办留在机器摘要、登记表或生产回执中。
3. “请甲方补充”“等待甲方确认”“甲方现在要做”“当前不宜前置”等内部协作语境，转译为已成立的市场意义、产品价值、销售表达或条件关系。正式成果自行形成可用判断，不向客户派研究任务。
4. 产物1、2的Markdown正式报告与JSON机器摘要物理分开。正式报告由同一结论重新编辑，不是删除内部词后的摘要导出。
5. 官方积极价值在任务口径允许时直接说明客户意义。价格、学区、产权、保值、交付和权益承诺继续按当前资料与授权边界表达。

## 四、结论与支撑就近组合

1. 数据判断附近放置机构摘要、来源短注或合格客户原声；完整链接、页码和检索记录进入来源附录或后台登记。
2. 有限客户观察只支持对应场景、语言和选择机制，不外推总体比例、普遍态度或成交归因。
3. 没有合格客户原声时保持缺位，不补造引语。顾问推演应按业务判断表达，不冒充真实访谈。
4. 竞品比较先承认对方为什么会被选择，再说明本案的避战、重设标准和取舍。

## 五、正式报告的编辑检查

1. 一句话只承载一个主判断；数据、原因、结果和动作过载时拆分。
2. 一句超过约70个中文字符、顿号达到3个或并列项超过5个时，优先归类或拆句；事实列举与客户原声按C级保持真实。
3. 区分事实数字、有限观察、趋势判断、原因推理与行动建议，不把内部推理写成外部事实。
4. 产品、客户、资源、组织能力和数据口径分别表达，避免把产品名堆成价值口号。
5. 删除“输出契约、Schema、validator、lint、prompt、工程门禁、机器摘要”等面向外部读者无意义的工程语言。
6. 产物1必须围绕当前项目按“城市／市场背景→区域改善结构→有效竞争圈→本案竞争答案”逐级递进。
7. 产物2必须围绕客户任务按“角色与处境→改变触发→希望进展→替代与取舍→促成与阻断→本案适配→下一步行动”闭合决策。

## 六、PPT、HTML、PDF和网页的额外检查

1. 可见标题、页签、卡片题头和图片题头写客户正在判断的关系、项目提供的内容或已经形成的选择结果。页面家族、证明角色、场景编号和制作步骤留在备注与消费包。
2. 逐页检查标题、引语框、数据表、来源、分页、裁切、重叠、乱码和移动端阅读。
3. 原本按一行设计的标题和短标签不能因文字框过窄而意外换行；优先压缩文案、扩大文字框或调整构图。
4. 对称构图、章节扉页、短卡片、页脚和横线按当前页面职责审定，软件默认占位不能替代人工视觉判断。
5. 文字扫描通过不能替代逐页视觉检查；载体通过不能替代业务判断和真人接受。

## 七、执行流程

1. 识别受众、用途、任务合同与锁定内容，并为文本划分A／B／C级。
2. A级句列出原句和支撑段落的全部信息点，判断属于层次、条件、多因裁定、分工或单纯否定。
3. 生成肯定式表达，完成语义覆盖与so-what测试；必要时形成主推句和备选。
4. 对A级文件运行：

   ```bash
   python3 tools/chinese_copy_lint/affirmative_statement_lint.py <file>
   ```

5. 对正式交付的B级正文运行：

   ```bash
   python3 tools/chinese_copy_lint/affirmative_statement_lint.py --report-only <file>
   ```

6. 使用`fixtures/client-review/`和当前报告校验器检查内部语言、外部资源、HTML安全与正式报告完整度。逐项人工复核机器命中。
7. 正式交付前确认：A层高影响句完成审校；B层扫描完成；C层事实与限制保持真实；客户正文完成去内部化；来源与结论相邻；正式载体完成逐页视觉检查。

## 八、例外与禁止事项

- 客户原声、甲方专名、事实数据、竞争适配边界及法律、价格、权益和交付限制，真实性高于句式整洁。
- 精确保留用户裁定的短语时，只使用当前项目的精确短语白名单，不允许用整段或整类句式白名单掩盖问题。
- 禁止正则批量自动改写复杂语义。
- 禁止为了“零命中”删除必要边界、客户原声或事实差异。
- 禁止让机器扫描单独批准策略质量、甲方可读性或正式验收。

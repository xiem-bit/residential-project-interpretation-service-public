# 住宅生产任务

先读当前用户材料与`AGENT_RULES.md`，按[路由](references/routing.md)读取本次产物规范；[输出合同](references/output-contract.md)只用于当前任务所需字段。新研究消费全部授权输入，纯编辑、排版、导出直接消费已有研究，不重做产物1。

1. 在现有项目合同明确受众、问题、输入及启用范围，按缺口使用已有上游接口，不因入口存在自动检索。
2. 产物1交付真实替代、竞品吸引力、同口径比较与本案位置；产物2独立交付真实选择、取舍、可争取需求和购买阻力。两者可独立启用，不要求完整套装。
3. 完整深化与正式方案按core/04保留至少三条机制不同且本案相称承接的竞争力；产物1不受数量或UE解法约束。UE制作只在相关任务启用后填写。
4. 产物3第二章保留生活主张、竞争理由、比较及购买任务；第三章用UE页面论证连接共用制作内容与预制讲稿，遵循core/06及现行模板。实例只迁移结构，当前事实、原声、名称与点位从本案认可输入装载。
5. 从当前Excel派生索引按生效语义选图，打开原图判断观看对象、机位和尺度。旧索引和已删案例不可用于候选。营销原文保真，只作表达参考。
6. 按页面职责完成甲方全文编辑，再用实际默认入口输出、回读可见文字并看图。沿用原有预排确认，不增加固定审查轮次；内部低成本修订由Codex自行完成。Grist不启用。
7. 产物4仅作内部制作衔接，遵循生产端原体系；产物5保持当前能力，消费同一判断及脚本引用。只修订受影响内容，不新增独立里程碑或数据库。
8. 使用`python3 scripts/verify_production_run.py <run-dir>`及当前载体实际检查，按[甲方写作](references/client-facing-writing.md)完成A／B／C检查。机器通过、实际输出、真人验收和公开发布分别报告。

实质方向冲突、推翻真人裁定、关键权益事实冲突或超授权动作才暂停对应部分。没有原子词典等明细，不阻塞已明确的研究和方案；不补造缺失生产标准。

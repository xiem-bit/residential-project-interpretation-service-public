# 产物 3 案例截图素材库

状态：`main_shared_asset_library / production_reference / product3_only / semantic_v2_imported`

## 一、用途

本库沉淀明源住宅 UE 的案例截图、用户订正后的生效业务语义与页面用途，供各项目的**产物 3**按需调用。它帮助项目把已经成立的竞争判断和客户选择，转成可看、可讲的 UE 展示方式。

案例仅证明明源可采用的展示方式、信息组织与交互表达。案例中的项目、城市、客户、数据、产品与业务结果不构成调用项目的事实，也不构成客户采纳或交付效果。

## 三、调用方式

1. 先在当前项目锁定页面要证明的购买意义、项目事实和 UE 画面；
2. Codex用该证明目的检索台账 F、G 列，自动选取语义相符的`CASE-编号`并写入当前项目后台装配字段；
3. 每张案例图在同一份产物3中默认只使用一次，避免一张画面承担多种证明职责；
4. 素材缺口在预排中以普通中文记录；需要人物／客群肖像等必装画面的客户正文页，必须先检索现有素材，无命中时新生产、复核并登记`CASE-编号`，不得以空案例位进入正式PPT；
5. 真人只需说“第10页换一张更能证明花园关系的案例图”等自然语言，Codex完成素材定位、替换和局部检查，不要求真人操作素材ID；
6. 面向甲方时，将案例标注为“明源住宅 UE 展示参考”或等价业务语言；来源与素材编号保留在备注。

视频截帧以静态画面的独立表达完整性为准：只保留主体、关系、标签或必要环境已经同时稳定呈现的帧，不因其承担视频开场、转场或过程铺垫而单独入库。同一视频包含多个镜头时，若不同镜头语言均能独立完整表达同一场景，可分别收入；同一镜头内优先保留内容最完整且构图差异明确的代表帧。建筑类 UE 镜头增加“横平竖直”检查：优先选择墙身竖线、檐口横线和入口轴线已经稳定，透视畸变较小，且主体、环境与标注完整同屏的时刻。

“城市慢行系统”素材以行人视角体验项目外部、紧邻项目本体的城市资源为边界。静态帧应同时呈现可步行空间、外部资源主体，以及项目本体、项目标注或足以说明邻接关系的空间线索；只有泛化景观、商业或品牌细节而无法看出项目及邻接关系的画面不进入有效库。

“城市配套资源”素材以项目为锚点，表现周边城市资源的种类、范围和空间连接。静态帧应至少完整呈现项目位置，以及多处配套节点、交通线路、到达路径或足以说明广域资源关系的城市环境；真实光照、云层、水面反射和高精建模用于增强三维场景可信度，但不能替代项目与配套关系本身。不同镜头可分别承担高真实度环境、自由视角总览、交通网络、广域节点覆盖和配套路径等证明职责。

“企业品牌展示”素材用于呈现企业实力、品牌定位及其支撑体系。静态帧应完整保留企业或品牌主体，并至少清楚呈现一种可独立理解的证明结构，如发展历程、产业版图、全国或重点城市布局、品牌理念、服务体系、文化资产、交付能力或代表项目谱系；仅有黑金视觉、光效、Logo 或转场而缺少完整信息结构的画面不入库。同一视频中的不同页面职责可分别保留，不因共享同一套品牌 UI 而强制合并。

“板块资源”素材用于展示大区域内部的小板块划分，或小板块内部的资源分布。静态帧应清楚保留区域或板块边界、层级关系、资源节点、路径连接或对标关系中的至少一种完整结构；当画面解释项目在板块中的位置与价值时，项目锚点应同时可识别。标签、色块、光效、环线、路径和信息面板需稳定展开后再截取；只有城市或自然景观氛围，但无法识别板块范围、资源分布或项目关系的画面不入库。同一单场景仅取信息最完整的稳定终态；不同证明机制可分别保留。

“项目/产品规划”素材以项目红线内的小区规划、社区配套、空间亮点与住宅产品亮点为边界。规划类静态帧应清楚呈现项目范围、楼栋排布、空间层级、标准层、台地关系、中心景观、主要尺寸或选房状态中的至少一种完整结构；产品类静态帧应让户型轴测、功能分区、跃层关系、阳台、景观视野或样板间具体功能空间可独立理解。文字解读、尺寸、楼层、户型小图和界面状态需稳定展开；室内镜头同时检查横平竖直、功能可辨和主要空间完整。只有装饰局部、过渡运镜或无法说明具体空间价值的画面不入库。同一视频中承担总图、户型、室内、景观或交互等不同证明职责的镜头可分别保留；连续漫游中语义和构图均高度重复的帧不叠加保存。

“项目红线内景观园林”素材用于展示社区园林、归家动线、连廊、架空层、下沉空间、会所外部、代建公园及植物营造。静态帧除空间关系完整外，优先选择阳光真实且充足的时刻：日照应能在树冠、灌木、铺装、水面、廊架或建筑界面上形成可辨的明暗层次，同时避免大面积死黑、过曝、纯逆光和不自然的统一亮面。森系场景允许保留真实树荫，但必须仍能看清步道、水景、活动空间或建筑边界，不能只凭树冠特写表达氛围。不同镜头可分别承担植物层次、归家路径、水景庭院、连廊光影、架空层活动和园林与楼栋关系等职责；同一空间只保留光照、稳定性和内容完整度最优的代表帧。

相同或相似业务语义不设置唯一约束，可保留不同项目、构图、景别、时段或界面状态的多张素材，通常以 3—5 张为软上限。达到软上限后只提示人工比较，不自动删除、不以语义近似强制去重；完全相同的文件仅在摄入时按文件校验值拦截重复保存。

## 四、边界

- 本库只供产物 3 调用；产物 4、5 不消费案例截图；
- 本案项目化图证优先由系统制作的地图／数据图／逻辑结构图和经业务语义复核的生成式图片承担；案例只证明 UE 展示方式，不替代项目总图、建筑、园林、户型、价格、权益或交付事实；甲方 PDF、微信文章和方案原始截图及其裁切、调色、遮罩、加字或轻度重绘变体不得进入正式成果；
- 不把案例截图写成当前项目实景、已有系统、客户反馈或已发生的业务结果；
- 不自动把案例填入每个版位。素材暂缺时保留清楚的案例位和证明目的；
- 非本库新增案例，先完成素材身份、语义和使用范围登记，再进入甲方版本。

## 五、规模与迁移规划

当前继续以 Excel 作为可视台账。“SQLite 主库＋原图文件夹＋缩略图缓存＋本机图库界面＋Excel 导出”是待人工裁定的后续方案，本轮只完成实现规划，不启动迁移。若获批准，SQLite 管理稳定编号、业务语义、标签、来源和使用状态，图片继续按文件存放，本机界面负责检索、筛选和并排比较，Excel 作为交换与人工复核格式。

建议在任一条件命中时提交迁移裁定：有效素材达到 500 张；Excel 文件达到 40—50 MB；一次保存或生成超过 5 秒；图片错位、丢失或打开失败开始重复出现；业务需要多标签组合筛选、并排比较或批量处理。未经人工批准不切换主库；裁定前继续保持编号与文件路径稳定。

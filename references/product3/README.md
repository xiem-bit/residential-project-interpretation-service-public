# 产物3页面语义与黄金组合参考

本目录沿用工程既有“页面语义”概念。“页面职责”是页面语义中的一个字段，不另建同义库。生产Owner先检索`page-semantics.json`，再参考当前黄金组合；只有当前项目的竞争机制、证据或演讲动作需要时才增删、调序和重组。

## 当前默认优先级

新的完整产物3先读取`examples/gold-product3-public-safe/`的整套组合，理解其叙事节奏和页面分工，再从17种页面语义中按当前项目重组。黄金组合的默认优先级高于孤立页面样例，但不刚性继承19页、具体页序或证明页数量。

复用历史成功页时，只继承页面语义、视觉结构、对象版位和表达节奏。标题、卡片、正文、竞品、客群、图像和结论必须由当前项目重新装载；任何来源项目的整页文案都不得进入正式新稿。

## 青岚澄境黄金组合

| 页码 | 页面语义 | 本页只负责什么 |
| --- | --- | --- |
| 01 | `P3-COVER-CLAIM` | 用一句话锁定本案要解决的购买问题 |
| 02 | `P3-BUYER-VOICE` | 用有限客户声音揭示比较条件，不外推比例 |
| 03 | `P3-CHOICE-SITUATION` | 把本案、两个直接替代与继续等待放入同一选择 |
| 04—06 | `P3-COMPETITION-MAP` | 分别回答进入候选、低密比较和行动等待 |
| 07 | `P3-ADVANTAGE-SYNTHESIS` | 将三张竞争地图压缩成三项机制判断 |
| 08 | `P3-VALUE-ANCHOR` | 给出全篇统一的购买价值 |
| 09 | `P3-SECTION-PROMISE` | 从项目理解切换到UE证明 |
| 10 | `P3-SC-OVERVIEW` | 交代三条竞争力各自承担的选择任务 |
| 11—13 | `P3-SC-SCENE`＋`P3-SC-PROOF` | 将三条竞争力分别转成客户获得、项目机制与画面证明 |
| 14 | `P3-FAMILY-SEGMENT` | 区分三类看房任务，不用面积代替家庭判断 |
| 15 | `P3-FAMILY-PATH` | 把一类家庭的处境、顺序、产品和展示串成路径 |
| 16 | `P3-UE-BLUEPRINT` | 将已成立语义投影为制作范围 |
| 17 | `P3-UE-FULLSCREEN` | 让未来案场体验一眼可见 |
| 18 | `P3-AI-RECOMMENDER` | 轻量预告推荐官怎样识别条件并打开内容 |
| 19 | `P3-CLOSING-OUTCOME` | 把全篇压缩成甲方能记住的结果 |

这一组合覆盖研究可信度、选择局面、三尺度竞争推导、超级竞争力、家庭路线、UE制作和推荐机制。其他项目可以压缩或展开，但必须保留完整论证和甲方可讲性。

## 删除与禁用清单

1. 不把内部生产流程、检索任务、schema、validator或QA状态做成甲方页面；
2. 不把研究方法单独扩写成低价值过程页；
3. 不在相邻页面重复解释同一竞争力；
4. 不恢复用户已删除的过渡页和空洞大标题页；
5. 不把产物5的完整交互内容提前塞进产物3，只做与采购决策相关的预告；
6. 不为了整齐让三条竞争力机械使用相同页数；
7. 没有独立购买判断、项目关系或图证，不新增证明页；
8. 不用面积、户型标签或人物照片直接推导家庭阶段；
9. 不把甲方原始截图及其轻度变体放入正式PPT；
10. 不为了接近黄金页数恢复已被业务删除的内容。

## 首稿完整度门槛

首次提交用户审阅的版本必须完成整体结构、正式文案、真实或公开安全图片装配、基本视觉排版、逐页渲染和客户可见内容检查。空槽稿、仅有标题的骨架稿、未装图片的结构试错稿和明显低密度草稿不能作为首稿提交。

页数、页序和证明页数量可以根据当前竞争机制调整，不需要逐页申请差异。最终以论证完整、甲方表达有效、图片合规和真人验收为准。

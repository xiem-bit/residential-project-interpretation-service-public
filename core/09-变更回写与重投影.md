# 变更回写与重投影

## 1. 识别语义变化

以下变化进入项目级变更：竞争场域、目标观念、目标客群、购买任务、价值锚点、SC、有效边界、制作项归属、AI 路线、关键项目／产品承接。

错字、字号、对齐、裁切、同职责换图和不改变购买理由的顺句属于局部载体修订。

## 2. 权威更新顺序

```text
新事实／新裁定
→ fact-conflict-gap-register
→ project-contract当前有效与被覆盖判断
→ 已启用或已有研究的受影响内容
→ semantic-core新版本
→ super-competitiveness-plan重新验收
→ chapter2／chapter3合同
→ 受影响的product3页面、product5场景
```

不得只修改最终 PPT 或网页后让上游合同保持旧战略。

业务语义冻结是当前制作依据，允许局部修正；不另设解冻、逐项审批和再次冻结流程。

## 3. 影响登记

只有发生实质语义变化时才创建`change-impact-registry.json`。每条变更登记：变更ID、触发事实、旧判断、新判断、理由、语义版本、受影响引用、无需变更的载体、执行Owner、状态、验证证据和被覆盖对象。

重投影遵循最小影响：只重做受影响内容。未启用产物可标记 `not_enabled_no_reprojection_required`，但不能把未处理写成已完成。

## 4. 真人例外

以下情况只暂停受影响分支并请求真人：多个同样有效且实质改变战略的方向；推翻用户既有裁定；关键身份、权益、价格或交付事实冲突；超出授权的发布、覆盖、权限或不可逆动作。

## 5. 完成门槛

变更完成要求：上游当前判断和被覆盖判断清楚；受影响SC重新检查，启用UE时同步其制作与引用；第二／三章保持一致；启用的产物3／5受影响引用均处理；跨产物一致性校验通过。载体视觉是否重做由adapter回执另行记录。

有第二章合同的现有装配入口保留chapter2_contract_path与reviewed_chapter2_basis；事实记录实质改变后，沿既有引用把相关标题、判断、图表、讲稿与制作内容返回原定向审阅，不因编号未变继承批准。纯空白调整不触发事实重审。只有本次使用的公司素材参与共享订正／退出核对，合法项目新增素材及历史交付保持。当前认可正文直接进入生产，不以旧业务稿和纠偏覆盖层作为构建起点。

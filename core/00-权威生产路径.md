# 权威生产路径

## 1. 单一权威入口

公开版的读取与执行顺序是：

```text
START_HERE.md
→ AGENT_RULES.md
→ RELEASE_STATUS.md
→ 本文件
→ PRODUCTION_PATH_MANIFEST.json
→ residential-production-orchestrator Skill
→ 当前项目原始材料
→ 本轮路由到的核心规范、模板、Schema和校验器
```

`PRODUCTION_AUTHORITY_MAP.json`记录私有主线权威文件如何被去项目化、平台中立化地映射进公开包。发生冲突时，根入口和本目录的现行规范高于历史 RC1 演示文件；`V0_1_RELEASE_SCOPE.md`、`RC1_E2E_VERIFICATION.json`及旧冷启动文件只说明历史载体适配状态。

## 2. 业务主链

本工程不是机械生产五个文件，而是共享一套业务语义、按商机阶段启用不同产物：

```text
已授权原始输入
  ├─ 甲方／正式资料：项目与产品底盘
  ├─ 顾问稿／历史成果：竞争场域与战略压缩
  └─ 客户声音／选择事件：替代、标准、否决与反例
        ↓
项目身份 + 任务模式 + 当前授权
        ↓
事实／冲突／缺口登记
        ↓
产物1：市场、区域、有效竞争圈、本案竞争答案
        ↓
产物2（按需）：购买任务与决策链
        ↓
统一业务语义核：八项真值
        ↓
3—4条不同机制的超级竞争力，各通过五项成立检查
        ↓
产物启用矩阵 + 高成本生产准入
        ├─ 产物3：第二章战略推导 → 第三章UE证明 → 载体适配
        ├─ 产物5 presales_focus：售前交互预演
        └─ 签约后产物4单树价值框架 → 产物5 delivery_full
```

PPTX、网页和 XMind 只位于分支末端。它们不产生上游战略答案。

## 3. 三个任务模式

- `real_project_delivery`：生产者从一开始读取全部已授权资料，目标是当前真实交付；
- `hidden_answer_replay`：先冻结盲态输入和产出，后揭晓参考答案，目标是评价独立发现能力；
- `non_research_task`：转译、导出、排版、发布或演示，继承已有语义，不重复研究。

系统能力评价必须分开记录盲态独立命中、内部事实补入、融合后命中、系统专业增量和真人顾问仍负责的部分。

## 4. 生产状态

业务路径只按以下顺序升级：

1. `rules_loaded`
2. `project_identity_closed`
3. `product1_complete`
4. `product2_complete_or_not_enabled`
5. `semantic_core_frozen`
6. `minimum_three_sc_pass`
7. `business_judgment_blind_review_pass`
8. `ue_solution_bridge_pass`
9. `cross_product_consistency_pass`
10. `production_path_replication_pass`

第 7 项必须由独立盲审产生；教程自检和机器校验不得自动写入 `pass`。载体状态使用独立命名空间，例如 `adapter.presentation.structure_pass`，不得覆盖业务状态。

## 5. 核心退回规则

- 项目身份不闭合：暂停受影响判断；
- 事实缺口会改变竞争结论：回附表 A；
- 少于三条成立 SC：返回产物 1／2、边界调整或专家推演；
- UE 无法证明：回到 SC 或项目承接，不用视觉文案掩盖；
- 新信息改变语义：按 `core/09-变更回写与重投影.md`处理；
- 仅载体能力不足：返回 adapter gap，不回写为住宅业务失败。

## 6. 完成定义

`production_path_replication_pass`只说明：独立使用者从原始输入完成业务主链，结构校验、盲审、UE桥接和跨产物一致性均通过。它不等于真实客户采纳、正式发布或业务效果已经发生。
